# Dokumen Database

**Continuous Development Phase**: The database has been instantiated. All future `.sql` scripts must be prefixed with the timestamp in `YYYYMMDD_hhmmss` format (example: `20260601_123456_alter_web_pdfs.sql`) instead of the ordered numbers of pre-instantiation scripts. Scripts must have dbmate:up and dbmate:down.

## Quickstart

1. Install [dbmate](https://github.com/amacneil/dbmate) and [PostgreSQL v18](https://www.postgresql.org/download/) including CLI tools psql, pg_ctl, pg_dump. Ensure they and initdb are added to PATH

2. Run script to create database and execute bootstrap, migrations, and seeds:

```bash
bash db/deploy-local/run-all.sh
```

3. Start database

Linux:

```bash
pg_ctl -D "$PWD/pgdata" -l "$PWD/logfile" -o "-k $PWD/pgdata -p ${PGPORT:-5432} -h ''" -w start
```

4. Stop database

Linux:

```bash
pg_ctl -D "$PWD/pgdata" -w stop
```

## PostgreSQL VSCode Extension by Microsoft

After installing the extension and starting the db, you can establish a connection by:

1. Press Add New Connection to open the Connect a Server window
1. At the top list of connection methods, select Connection String instead of Parameters
1. Enter your connection string postgres://your-user@localhost/dokumen?sslmode=disable. Replace your-user with your OS username
1. Change Authentication Type to None instead of Password
1. Name your connection localconn
1. Press Save & Connect and then the connection will appear in the PostgreSQL extension tab (the elephant)
1. If your db server is not running, the connection is not running.
The extension will save your connection details so you only need to refresh the connection after starting the db.
Do this by right-clicking on localconn under CONNECTIONS > Servers and pressing Refresh.

## Schemas

Each app has its own schema that it can write to and it can read from the other app's schemas. Information controlled by the Dokumen maintainers (not modified by apps) should be in schema public.

## Files

### migrations\

SQL scripts that create objects

### seeds\

SQL scripts that INSERT data into objects defined in migrations

### better-auth_migrations\

SQL scripts created by "bun x @better-auth/cli@latest generate". Modified to use schema auth and user auth_role.

### schema.sql

Generated by pg_dump to condense an empty version of the database using the migration scripts as of 12-30-25. Used to help LLMs understand the db. Not used in db creation.

## Role-based Access Control

**Rules:**

- Public schema should not be written to by any app (only seeds executed by a maintainer) and can be read by any app
- Better Auth in web should use ROLE AUTH_USER
- `web` should use ROLE WEB_USER that can read/write SCHEMA WEB and AUTH (and CORE) and read other schemas
- `api` should use ROLE API_USER that can read/write SCHEMA API (and CORE) and read other schemas (besides AUTH)
- `workers` should use ROLE WORKERS_USER that can read/write SCHEMA WORKERS (AND CORE) and read other schemas (besides AUTH)
- A few exceptions are allowed when logically useful where tables can be written by multiple apps if they exist in CORE schema
